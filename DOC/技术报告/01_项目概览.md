# pgvector HNSW 优化技术报告

## 第 1 章：项目概览

### 1.1 项目定位

本项目在 [pgvector 0.8.4](https://github.com/pgvector/pgvector) 基础上，针对 HNSW 向量索引的**查询延迟**、**参数自适应**、**构建性能**和**并行扩展性**做系统性优化，面向 RAG（Retrieval-Augmented Generation）、AI Agent Memory、向量搜索等 AI Infra 典型场景。

关键交付：

1. **代码优化**：6 个可灰度 GUC + `PrefetchBuffer` 预取 + 半动态 `ef_search`
2. **观测脚手架**：build 期 I/O、并行加速比、recall/latency 全套 benchmark
3. **实验验证**：200k 行 128 维数据上 **p99 延迟降低 55.9%**，Recall 完全一致
4. **文档**：设计文档、实现导览、benchmark 报告、简历表述

### 1.2 问题背景

#### 1.2.1 AI Infra 场景对向量检索的要求

RAG 和 AI Agent 系统的典型查询模式：

```sql
SELECT chunk_id, content
FROM   knowledge_base
WHERE  tenant_id = $1                          -- 多租户过滤
  AND  created_at > NOW() - INTERVAL '30 days' -- 时间过滤
ORDER  BY embedding <-> $2::vector             -- 向量相似度排序
LIMIT  10;                                      -- Top-K
```

这类查询的特点：

- **在线路径**：LLM 生成 prompt 前必须完成检索，延迟直接影响首 token 时间
- **强过滤 + 强排序**：先做 WHERE 过滤，再做 ORDER BY 向量距离
- **Top-K 通常很小**：5~20，几乎不会 fetch 完整候选集
- **Recall 敏感**：漏掉一个相关文档，LLM 回答质量断崖式下降
- **并发不高但持久**：每个用户会话都在跑，长尾延迟影响 P99 SLA

#### 1.2.2 pgvector HNSW 的性能特征

HNSW（Hierarchical Navigable Small World）是分层图索引：

- **上层稀疏**：入口点少，导航快
- **下层稠密**：第 0 层包含所有向量，邻居数 ~2m
- **查询流程**：从上层入口逐层贪心下降，第 0 层做 beam search（`ef_search`）

pgvector 的 HNSW 实现有几个性能瓶颈：

1. **随机 I/O**：邻居节点分布在不同 index page 上，触发 buffer miss 时**同步阻塞**
2. **`ef_search` 静态**：无法根据过滤情况动态调整，容易召回不足
3. **build 期黑盒**：没有官方工具量化 I/O vs CPU 占比
4. **并行扩展性未知**：workers 加多少最优？瓶颈在哪？

### 1.3 优化路线

按"低侵入、可灰度、可 benchmark"三原则，我们把优化拆成 4 个 Phase：

| Phase | 目标 | 代码改动 | 风险 | 状态 |
|---|---|---|---|---|
| **1** | 查询路径 Buffer Pool 预取 | `hnswutils.c` + GUC | 低 | ✅ 已实现 |
| **2** | `ef_search` 半动态扩展 | `hnswscan.c` + GUC | 低 | ✅ 已实现 |
| **3** | 构建期 I/O 观测 | 无代码改动，只加脚本 | 零 | ✅ 已观测 |
| **4** | 并行 build 锁分析 | 无代码改动，只加脚本 | 零 | ✅ 已观测 |

设计原则：

- **默认 off**：所有新 GUC 默认关闭，行为完全等价官方 0.8.4
- **可灰度**：通过 `SET hnsw.hot_cold_enabled = on` 单库/单会话切换
- **可回退**：`OFF` 即回退，无需重启 PG，无需重建索引
- **零磁盘格式改动**：不改 HNSW 元页、元素页、邻居页格式
- **零 VACUUM/INSERT 影响**：这两条正确性关键路径完全不动

### 1.4 关键实验数据

**测试环境**：PostgreSQL 18.4 on Windows，200k 行 128 维随机向量，HNSW `m=16, ef_construction=64`。

#### Phase 1 收益（Buffer Pool Prefetch）

| ef_search | 指标 | off | on | 改善 |
|---:|---|---:|---:|---:|
| 40 | Recall@10 | 0.198 | 0.198 | 0% |
| 40 | avg latency | 6.51 ms | 4.79 ms | **-26.5%** |
| 40 | p99 | 9.58 ms | 7.98 ms | -16.7% |
| 200 | Recall@10 | 0.478 | 0.478 | 0% |
| 200 | avg latency | 22.95 ms | 15.42 ms | **-32.8%** |
| 200 | **p99** | **48.09 ms** | **21.23 ms** | **-55.9%** |

#### Phase 2 收益（半动态 ef_search）

带 `WHERE tag = 42` 过滤（约 1% 命中率）：

| 配置 | Execution Time | shared hit |
|---|---:|---:|
| `ef_search_auto = off` | 16.9 ms | 12660 |
| `ef_search_auto = on` ×2.0 | **13.2 ms (-21.8%)** | 15413 |

#### Phase 4 观测（并行加速比）

| workers | build time | speedup |
|:---:|---:|---:|
| 0 (serial) | 11736 ms | 1.00x |
| 2 | 5500 ms | **2.13x** |
| 4 | 5028 ms | 2.33x（边际递减） |
